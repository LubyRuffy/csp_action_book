# 《公式是怎么变成代码的》
## 副标题：从数学关系到程序步骤的思维转换课

这次把范围严格收住：**不讲算法选择，不讲 DFS、BFS、贪心、动态规划，也不把它写成另一套算法教材。**本书只解决一个更早、更基础的问题：

> 学生明明看懂了数学关系，为什么还是不知道代码该怎么写？

---

# 一、创作背景

在 C++ 和 CSP-J 入门教学中，经常出现一种被误判为“编程能力差”的现象：

学生知道把 `3` 插入 `[1,5]` 后会得到 `[1,3,5]`，却不知道为什么必须先把 `5` 移到右边；知道两个变量应该交换，却会写出：

```cpp
x = y;
y = x;
```

知道：

\[
S=a_1+a_2+\cdots+a_n
\]

却不知道代码为什么需要一个从 `0` 开始、不断变化的 `sum`；知道：

\[
M=\max(a_1,a_2,\ldots,a_n)
\]

却不知道为什么要保存“目前看到的最大值”。

这些学生缺少的不是数学知识，也不是算法知识，而是一种中间能力：

# 程序化映射能力

也就是把数学中的关系、结果和变化，转换为计算机可以按照顺序执行的状态更新。

数学和代码面对的是两个不同的世界。

数学通常描述：

- 什么关系成立；
- 最终结果是什么；
- 多个量应当怎样同时变化。

代码必须描述：

- 旧值存在哪里；
- 先修改谁；
- 后修改谁；
- 哪些值会被覆盖；
- 需要重复多少次；
- 从哪个下标开始；
- 在哪里停止。

例如，数学可以轻松写出：

\[
x'=y,\qquad y'=x
\]

但代码不能让两个赋值同时发生。计算机只能一句一句执行，所以必须保存旧值：

```cpp
int temp = x;
x = y;
y = temp;
```

这就是本书最核心的矛盾：

> **数学擅长描述静态关系，程序必须展开动态过程。**

完整的转换链条应当是：

\[
\boxed{
\text{数学关系}
\rightarrow
\text{旧状态与新状态}
\rightarrow
\text{更新顺序}
\rightarrow
\text{变量和下标}
\rightarrow
\text{代码}
}
\]

本书专门训练这条链，而不是假装学生看到公式后，代码就会自行从键盘里长出来。

# 二、本书定位

本书面向已经初步接触变量、`if`、循环和数组，但仍然经常出现“数学会做，代码不会写”的学习者，主要适合小学高年级至初中阶段，也适合 CSP-J 初学者作为语法课与算法课之间的过渡教材。

本书不是：

- C++ 语法手册；
- 算法模板大全；
- 数学习题集；
- CSP-J 刷题书；
- 以背代码为目标的速成教材。

本书解决的是：

> **一个数学想法，究竟怎样一步一步落到变量、赋值、条件、循环和数组下标上。**

代码统一使用简洁的 C++，但书中训练的能力不依赖具体语言。换成 Python、Java 或其他语言，底层思维仍然成立。

# 三、核心教学目标

## 1. 理解数学等号与程序赋值的区别

学生必须真正理解：

```cpp
x = x + 1;
```

不是数学方程，而是一个过程：

1. 读取旧的 `x`；
2. 计算 `x+1`；
3. 用结果覆盖原来的 `x`。

## 2. 建立旧状态与新状态意识

每次修改变量前都要问：

> 原来的值以后还需不需要？

如果还需要，就必须先保存。

这条原则贯穿：

- 交换变量；
- 数组插入；
- 数组移动；
- 递推更新；
- 多变量同步变化。

## 3. 学会设计“过程中的变量”

数学只给最终结果，程序往往需要中间状态，例如：

| 数学目标 | 程序中的状态 |
|---|---|
| 总和 | `sum`：目前已经累加的和 |
| 个数 | `count`：目前已经找到多少个 |
| 最大值 | `maximum`：目前看到的最大值 |
| 插入数字 | `current`：暂时拿在手里的数字 |
| 是否存在 | `found`：到目前为止是否找到 |
| 递推数列 | 前几个尚未被覆盖的旧状态 |

## 4. 理解执行顺序

学生应能判断：

- 为什么交换需要临时变量；
- 为什么数组插入必须从右向左移动；
- 为什么数组删除通常从左向右覆盖；
- 为什么递推更新时不能随意调换语句；
- 为什么某些值必须先计算、后写回。

## 5. 掌握常见数学到代码的映射模式

读完后，学生应能熟练完成：

- 等式到赋值；
- 分情况到 `if/else`；
- “对每一个”到循环；
- 求和到累加器；
- 计数到计数器；
- 最大最小到当前候选值；
- 数列下标到数组；
- 区间到循环边界；
- “至少存在一个”到布尔变量；
- 同时变化到临时变量和顺序更新。

# 四、故事背景

故事发生在一个原创的方块世界中。这里有自动农场、村民交易所、矿物仓库、铁路运输线和红石工坊，整个世界看起来非常先进，直到人类试图让机器人替自己干活。

主角托马斯是一名十三岁的皇家仓库见习管理员。他数学不错，也很会心算，但每次写程序都会遭遇同一个问题：

> 他知道结果应该是什么，却不知道该怎样让机器人一步一步做出来。

导师 Notch 把他带进皇家自动化工坊，交给他一台名叫 R-01 的机器人。

R-01 不笨，也不聪明。它只具备计算机最诚实的品质：

- 不会猜；
- 不会脑补；
- 不会“差不多”；
- 严格按照顺序执行；
- 数据被覆盖以后绝不会凭感情替你找回来。

托马斯说：

> “把 3 放到 1 和 5 中间。”

R-01 直接执行：

```cpp
a[1] = 3;
```

然后报告：

> “任务完成。数字 5 已永久消失。”

托马斯：

> “谁让你把它删了？”

R-01：

> “你没有告诉我先把它搬走。机器不对人类未表达的愿望负责。”

全书的幽默主要来自人类直觉与机器执行之间的冲突。故事不是装饰，而是让“覆盖、保存、顺序、边界”等抽象问题真正发生。

# 五、写作要求

## 1. 故事必须推动知识产生

每章不能先给定义，再找故事包装。必须先制造一个具体冲突：

- 数字被覆盖；
- 箱子搬错方向；
- 机器人多算一次；
- 循环永远停不下来；
- 平均数因为整数除法变小；
- 插入数据后最后一个元素神秘失踪。

知识必须是为了解决故事中的麻烦而出现的。

## 2. 语言必须幽默，但不能为了搞笑牺牲逻辑

笑点主要来自：

- R-01 对模糊命令的机械执行；
- 托马斯想当然造成的事故；
- 村民只关心自己的绿宝石；
- 苦力怕总在边界条件测试时出现；
- 红石机关忠实执行错误逻辑。

幽默必须帮助读者记住概念。例如“数学里的数字会自动让路，数组里的数字没有这种教养”，用来解释数组插入，而不是单纯插入与知识无关的游戏梗。

## 3. 保持强烈的画面感

每个赋值都要能够在读者脑中形成动画。

例如：

```cpp
a[2] = a[1];
```

不能只解释为“把 `a[1]` 赋值给 `a[2]`”，而应描述为：

> 把第二格中的 `5` 复制到第三格。原来的第二格仍然是 `5`，现在仓库里暂时出现了两个 `5`。

学生必须看见内存状态怎样变化。

## 4. 每章遵循统一结构

每章固定包含七个环节：

1. **故事事故**：机器人执行了一个看似合理但错误的命令。
2. **数学视角**：人类看到的关系或最终结果。
3. **内存视角**：变量和数组格子现在分别是什么。
4. **逐帧变化**：每执行一句，状态怎样改变。
5. **代码生成**：从变化过程自然得到代码。
6. **错误博物馆**：展示常见错误为什么必然出错。
7. **翻译训练**：数学到代码、代码到状态双向练习。

## 5. 不允许代码突然出现

任何代码出现前，必须先回答：

- 现在已知什么？
- 需要记住什么？
- 下一步要改变什么？
- 原来的值是否还需要？
- 应该先改哪一个？
- 重复动作何时结束？

代码是推理结果，不是需要背诵的神谕。

## 6. 控制代码规模

前半本书每个核心代码片段尽量控制在 3 至 8 行；后半本书可以逐步增加，但单个案例不应超过 20 行。

每一行必须能够用一句生活动作解释。无法解释的行，通常说明内容跨度太大，或者作者又开始拿“初学者应该懂”替自己的懒惰开脱。

## 7. 使用状态表，而不只使用流程图

每个关键案例都应提供逐步状态表：

| 执行语句 | `a[0]` | `a[1]` | `a[2]` | `current` |
|---|---:|---:|---:|---:|
| 初始 | 1 | 5 | ? | ? |
| 保存 | 1 | 5 | ? | 3 |
| 右移 | 1 | 5 | 5 | 3 |
| 插入 | 1 | 3 | 5 | 3 |

状态表是数学与代码之间最可靠的桥梁。

## 8. 练习必须验证思维转换，而不是只测运行结果

核心题型包括：

- 下一句执行后，哪些变量会变化？
- 哪个旧值即将丢失？
- 以下语句应该按什么顺序排列？
- 为什么必须从右向左移动？
- 请为这段代码“配音”。
- 给出数学描述，设计需要保存的状态。
- 给出错误代码，画出它的实际执行过程。
- 不写代码，只补完整状态变化表。
- 根据状态变化表还原代码。

## 9. Minecraft 元素必须服务于模型

可以使用：

- 仓库格子表示数组；
- 物品栏表示有限容量；
- 村民交易表示条件判断；
- 红石脉冲表示顺序执行；
- 自动农场表示循环；
- 铁路坐标表示下标；
- 苦力怕表示意外边界和状态破坏。

不能只是把“数字”换成“钻石”便宣布故事化完成。给数学题戴一个方块头盔，仍然只是数学题。

## 10. 严格控制内容边界

本书可以使用查找、插入、删除、简单数列等作为载体，但不进入算法识别与复杂算法体系。

不系统讲：

- 冒泡、选择、快速排序等排序算法；
- DFS、BFS；
- 贪心；
- 动态规划模型；
- 图论；
- 算法复杂度决策。

简单递推可以出现，但目的仅是训练旧状态保存和更新顺序，而不是教授动态规划。

# 尾声　“我懂了”到“我能写出来”

托马斯终于明白，代码不是数学答案的另一种写法。

数学告诉他：

> 结果之间有什么关系。

程序要求他说明：

> 从当前状态出发，先做什么，再做什么，怎样避免丢失信息，什么时候停止。

真正的编程能力，不只是知道答案，而是能把答案展开为一条机器可以走完的道路。

# 《代码是怎么来的》
## 副标题：从动作到程序的计算思维课

---

# 一、创作背景

## 1. 为什么要写这本书

在教授 CSP-J、算法和 C++ 编程的过程中，发现大量初学者存在一个共同问题：

他们并不是不会数学，也不是完全不懂算法。

很多学生能够理解：

- 排序的目标；
- 动态规划的递推关系；
- DFS 的搜索过程；
- 贪心的选择原则；

但是一旦要求写代码，就会出现：

- 不知道变量应该保存什么；
- 不理解为什么需要 `current`、`temp`、`visited`；
- 不知道循环到底应该重复什么动作；
- 不理解递归为什么要调用自己；
- 看得懂算法，却写不出程序。

问题的根源不是算法知识不足，而是缺少一道关键桥梁：

> **如何把人类的想法，转换成计算机可以执行的一步一步动作。**

目前大多数编程教材直接从：

```
问题
↓
算法
↓
代码
```

跳跃。

但真实的程序设计过程应该是：

```
现实问题
↓
抽象问题
↓
动作分解
↓
状态设计
↓
变量设计
↓
程序代码
```

本书专门填补中间缺失的“动作建模”阶段。

# 二、核心理念

## 1. 程序不是魔法，而是一份动作说明书

计算机不会理解：

- “整理一下”
- “找到最大的”
- “走最短路线”
- “把数字插进去”

这些都是人类语言。

计算机只能执行：

- 读取；
- 保存；
- 比较；
- 移动；
- 交换；
- 记录；
- 重复；
- 判断。

所以：

> 编程的本质，是把一个模糊目标拆解成计算机能够执行的一系列动作。

---

## 2. 算法学习的真正顺序

本书建立一个新的学习模型：

```
看到问题

↓

想象现实中的解决过程

↓

拆解动作

↓

确定需要保存的信息

↓

设计状态

↓

转换成代码
```

例如：

插入排序不是：

```
for + while + 数组移动
```

而是：

```
拿起新来的牌

↓

向左寻找位置

↓

比它大的牌向右移动

↓

腾出空位

↓

放入新牌
```

代码只是这个动作过程的另一种表达。

# 四、故事背景设计

## 世界观

故事发生在 Minecraft 风格的方块世界。

主角：

## 托马斯（Thomas）

13岁少年。

喜欢建造、探索和发明。

他发现：

自己能够解决很多现实问题，但是不会让计算机帮忙。

例如：

- 如何整理仓库？
- 如何规划铁路？
- 如何寻找地下矿洞？
- 如何管理村民交易？
- 如何计算资源数量？

---

## 引导角色

### Notch

以 Minecraft 创造者形象出现。

不是传统老师，而是：

一位创造者和工程师。

他的理念：

> 一个伟大的程序，不是写出来的，而是想清楚以后自然产生的。

他带托马斯进入“自动化工坊”。

---

## 核心道具

### R-01机器人

一个不会思考，只会执行命令的机器人。

它是整本书的教学工具。

托马斯必须学会：

如何把自己的想法告诉机器人。

例如：

托马斯：

> “帮我整理箱子。”

机器人：

> “整理是什么？”

于是托马斯开始学习：

拆解动作。

# 五、写作风格要求

## 1. 必须故事驱动

禁止：

```
定义：

插入排序是一种……
```

改为：

```
托马斯发现，仓库管理员每天整理箱子时，都在做同一件事情……
```

知识必须从故事中自然产生。

---

## 2. 必须遵循：

```
故事
↓
问题
↓
思考
↓
动作
↓
抽象
↓
代码
↓
练习
```

每个知识点必须回答：

为什么需要它？

它解决什么问题？

---

## 3. 代码不是主角

不要：

先贴50行代码。

应该：

先让读者理解：

“机器人下一步应该做什么”。

然后代码出现。

代码只是：

动作翻译。

---

## 4. 强调第一性原理

每个概念必须追问：

为什么？

例如：

变量：

不是：

> 用来存储数据。

而是：

> 机器人忘记事情，所以需要一个地方保存过去的信息。

循环：

不是：

> 重复执行代码。

而是：

> 当一个动作需要执行很多次时，人类发明了一种描述重复的方法。

数组：

不是：

> 一组连续空间。

而是：

> 当机器人需要同时管理很多相同类型的东西时，需要一个编号仓库。

# 六、章节统一结构

每章固定采用：

## 1. Minecraft 场景故事

例如：

- 仓库管理；
- 村民交易；
- 铁路规划；
- 矿洞探索；
- 怪物追踪。

---

## 2. 一个真实问题

例如：

“如何让机器人整理100个箱子？”

---

## 3. 人类解决方式

先不用代码。

让学生思考：

如果自己做，会怎么做？

---

## 4. 动作拆解

例如：

```
找到箱子

比较

移动

记录

重复
```

---

## 5. 计算机抽象

转换为：

```
变量

循环

条件

数组

函数
```

---

## 6. 代码实现

代码必须短小。

每一行代码都有对应动作解释。

禁止：

只解释语法。

---

## 7. 思考挑战

设计问题：

让学生预测：

下一步机器人会做什么？

或者：

如果改变条件，会发生什么？

---

# 七、核心教学目标

读完整本书后，学生应该形成：

## 第一能力：动作拆解能力

看到：

“排序”

想到：

```
比较

移动

交换

保存
```

---

## 第二能力：状态设计能力

知道：

什么时候需要：

```
变量

数组

集合

队列

栈

DP数组
```

---

## 第三能力：代码翻译能力

能够把：

```
机器人动作流程
```

转换成：

```
程序结构
```

---

## 第四能力：算法迁移能力

学会：

不是记：

“这题用DFS”。

而是理解：

“这个问题需要不断进入、探索、回来。”

所以自然选择DFS。

---

# 八、全书核心一句话

> **算法告诉我们应该怎么解决问题，代码告诉计算机具体怎么执行，而《代码是怎么来的》教会学生搭建两者之间最重要的桥梁：把想法变成动作，把动作变成程序。**

这本书和《算法从数数开始》形成互补：

《算法从数数开始》：

> 人类如何发现算法。

《代码是怎么来的》：

> 人类如何把算法告诉计算机。

两本书合起来，覆盖一个孩子从“会思考”到“会创造程序”的完整路径。
